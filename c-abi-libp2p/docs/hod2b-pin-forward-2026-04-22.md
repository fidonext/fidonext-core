# Ход 2B — pin-forward libp2p 0.56 → 0.57 (2026-04-22) — **DEAD END**

## Status

**Closed without execution.** libp2p 0.57.0 / libp2p-relay 0.22.0 / libp2p-swarm 0.48.0 / libp2p-core 0.44.0 are **unreleased** on crates.io — they exist only in the unreleased section of `libp2p/rust-libp2p@master`'s per-crate CHANGELOG staging. `cargo update` against `libp2p = "0.57"` fails at dependency resolution. Cargo.toml reverted to `"0.56"`; nothing else changed.

Source inspection on unreleased master vs shipped 0.21.1 confirms — byte-for-byte identical crash path (`priv_client::Behaviour::handle_established_outbound_connection` → `MultiaddrExt::is_relayed` → `multiaddr::Iter::next` → `Protocol::from_bytes`). The single functional change in the 0.22 relay crate (`Behaviour::set_status`) touches `relay::Behaviour` server only, not the client behaviour where our crash lives. **Even when 0.57 ships on crates.io, it will not fix the TD-46/TD-50 UAF.**

Next move: Ход 2C (constructor-time exclusion of `relay::client::Behaviour` + transport-side `relay::client::new(...)` — extend TD-47 past the runtime toggle to compile/compose a variant without relay-client entirely for v0.0.7).

cheap explanation for ship-gate4/5/7/8 SIGSEGVs, before moving to more invasive paths
(constructor-time exclusion of `relay::client::Behaviour`, Ход 2C).

## SIGSEGV prediction
**Will reproduce.** The crash path
(`priv_client::Behaviour::handle_established_outbound_connection` → `<Multiaddr as MultiaddrExt>::is_relayed`
→ `<multiaddr::Iter>::next` → `Protocol::from_bytes` with `NULL` `data_ptr`) is unchanged between
`libp2p-relay` 0.21.1 and 0.22.0:

- `protocols/relay/src/priv_client.rs` at the crash site is byte-for-byte identical.
- `protocols/relay/src/multiaddr_ext.rs::is_relayed` is `self.iter().any(|p| p == Protocol::P2pCircuit)`
  in both versions.
- `protocols/relay/src/priv_client/transport.rs` differs only in import ordering.

The auto-HOP-advertisement change only touches `relay::Behaviour` (server) event emission, not the client
behaviour's connection-establishment callbacks where our crash lives.

Therefore Ход 2B is not a fix. It is:
1. A cheap experiment ruled out.
2. A clean pinning to the most recent minor for everything else (defense in depth for unrelated bugfixes
   in transitives we did not audit line-by-line).
3. Green evidence that the toolchain + cross-compile still work on the newer wave.
